## Causa y patrón reutilizado

Material V2 aplica sticky exclusivamente a `table.next-materials-table [data-buttons]`; Ventas usa `next-data-table` sin ese selector. El problema no es un permiso ni una pérdida de acciones. Se amplía el mismo bloque CSS a `.next-sticky-action-cell` y se reutiliza su ancho compacto, right:0, capas 2/3, fondo opaco, borde y sombra. No se copia el ancho global de Material a las demás tablas.

El adaptador compartido `initializeNextStickyTableActions` detecta encabezado final Acciones/Acción/Opciones, `data-buttons` o marcador explícito `.next-action-column`. Añade sólo clase de presentación a encabezado/celdas equivalentes, sin tocar atributos contractuales. Las tablas sin encabezado simple o con spans se dejan sin inferencia; filas vacías/detalle con colspan no se fijan. Se preserva la versión móvil de tarjetas.

El CSS original no era reutilizable sin ampliarlo porque estaba limitado a Materiales. Hay una mejora compartida (no 0 CSS): extensión de cuatro grupos de selectores existentes y estados opacos striped/selected/active/success/danger con tokens existentes. Sin CSS inline productivo ni dependencia nueva. El CSS inline del test sólo fuerza un dataset sintético ancho.

El portal existente `initializeNextRowActions` mueve el menú a body; no fue modificado. Conserva iconos, Escape, handlers, condiciones y acciones. FixedColumns se detecta y se omite; no dos mecanismos de fijación. Los cambios AJAX y eventos DataTables refrescan sólo clases, sin cambiar filtros, orden, selección ni paginación.
